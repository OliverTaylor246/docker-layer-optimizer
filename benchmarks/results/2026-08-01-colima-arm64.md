# Benchmark result: Colima ARM64, 2026-08-01

Five repetitions per change type and layout using the committed benchmark harness after adding a unique per-run cache salt.

Environment: macOS 26.5.2 ARM64, Colima, Docker client/server 29.7.1/29.5.2, Buildx 0.36.0, Python 3.9.6.

| Case | Control source edit median | Optimized source edit median | Source savings | Control → optimized rebuilt steps |
|---|---:|---:|---:|---:|
| Python | 1.987 s | 0.453 s | 77.2% | 2 → 1 |
| Node | 0.983 s | 0.431 s | 56.2% | 2 → 1 |
| Go | 2.951 s | 2.791 s | 5.4% | 4 → 2 |
| Monorepo | 2.029 s | 0.446 s | 78.0% | 2 → 1 |

Dependency-manifest edits were intentionally not improved: median differences ranged from -1.9% to +1.1%, which is noise at this scale because both layouts must repeat dependency work. This is a useful negative control.

No-op raw Docker medians were 0.306–0.324 s. `dlo` wall medians were 0.370–0.397 s, a 0.061–0.084 s process-level difference. The observer directly attributed 0.020–0.024 s median to context snapshot plus image inspection; remaining wall difference includes Python startup, state locking/serialization, and process scheduling.

These results demonstrate the expected cache decision and provide one local timing sample; they are not a promise of equivalent savings on other projects or deployment infrastructure. Reproduce with the instructions in [the methodology](../../docs/benchmarking.md).
